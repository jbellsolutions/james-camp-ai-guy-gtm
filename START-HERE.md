# Guided self-install

Start with the [complete requirements checklist](docs/READY-TO-RUN.md) and [toolkit inventory](docs/TOOLKIT.md). This is the go-to-market workforce: CSO, campaign team, Conversion Specialist and optional Revenue Partnerships Program Manager.

The setup agent does the work. James supplies business decisions, private credentials and account consent.

1. Read charters/PROJECT.md, docs/TEAM-CONTRACT.md and docs/SOURCES.md. Confirm GitHub access (`gh auth status`); if absent, guide browser/device authentication. Install GitHub CLI on the selected target using official instructions if authorized; on James’s own computer get authorization before adding system tools.
2. Ask: “Do you want this on an existing Orgo computer or a VPS such as DigitalOcean?” Inspect target OS, RAM/disk, existing deployments, Docker and occupied ports. Use the Orgo API/computer tools or SSH. Provision new paid capacity only under his authorization. Read docs/DEPLOYMENT.md.
3. Ask: “Cold Email, Conversations & Conversion, or both?” Ask for offer, ICP, truthful proof, exclusions, sender identity, booking link, brand voice, geographic markets, human escalation route, acceptable spend and campaign limits. Record decisions privately with docs/ONBOARDING.md.
4. Ask: “Do you already have data, want to upload a list, or want me to source leads?” Show optional Data Box/providers and BrowserBox; list missing keys and costs without blocking an uploaded-list route. Ask: “Instantly or Smartlead?” Offer PlusVibe for a client setup if requested; discover its current official API before creating a skill. Never claim an MCP exists without verification.
5. Run `python3 scripts/check.py` and tests. Run `python3 scripts/install.py --mode both --prepare-only --state-root /srv/james-gtm` (select his mode). This generates private per-install `agent.env` files and all selected profile assets. Configure credentials through private entry, never command arguments or chat. The baseline runtime uses Fireworks; another provider requires reviewed config changes and an inference smoke test.
6. On a clean Linux target, install Docker/Compose with the vendored provision-vps.sh only after reviewing it. Run `python3 scripts/install.py --mode both --deploy --state-root /srv/james-gtm`. It runs the pinned existing GTM installer independently for each stack, overlays client profile assets/config, then restarts and verifies each runtime. Existing custom assets are preserved and unresolved conflicts block completion.
7. Connect Slack using docs/SLACK.md. Automate manifest validation/creation when a workspace app-configuration token is available; otherwise use the manifest UI. Owner still authorizes installation and enters app-level/bot tokens privately. Configure allowed Member IDs and test one harmless message/reply.
8. Ask: “Do you want GoHighLevel Agent 4 connected to your location?” Install the bundled CLI in its own venv, register MCP in the target profile, probe scoped access, import/create only designated test records and test SMS with an explicitly consented test recipient. Native GHL AI and other automations must not race the relationship agent.
9. Offer optional Composio. Use its installed CLI or official install procedure; authenticate privately, connect only selected apps and accounts, inspect schemas before writes. It is an optional connection path, not a second executor.
10. Configure authenticated event delivery or polling reconciliation for the chosen sequencer and GHL. Read docs/EVENTS.md. Verify duplicate replay, immediate sequence stop, opt-out, durable CRM retry, context brief and unknown send reconciliation. Provider auth/capabilities determine the adapter; do not expose the normalized bridge directly to arbitrary unsigned provider posts.
11. Ask: “Would you also like Revenue Partnerships Program Manager to manage partner relationships, connections, context and personalized communication?” Enable the optional profile on the conversation stack, using the same cards and sender ownership. No need for a third installation.
12. Configure CSO coverage, source mappings and review schedule with docs/CSO.md. Verify its daily brief and assignment/receipt loop. Cross-install dispatch and journal synchronization require explicit verified mappings; they are not enabled automatically. Complete docs/ACCEPTANCE.md. Deliver templates/COMPLETION.md with evidence. External launch needs a recorded scope covering list version, exact copy, sender, provider campaign, windows, caps, budget, reply playbook and expiry. Existing approved scope counts; do not ask again for covered actions.
